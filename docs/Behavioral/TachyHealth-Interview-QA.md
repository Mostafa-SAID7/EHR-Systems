## Q8: "Tell Me About a Time You Failed"

### What They're Testing
- Humility
- Learning ability
- Accountability

### TachyHealth-Aligned Answer
```
"I built a caching layer that broke production.

SITUATION: Our medical records system was slow (2s response time). Users 
complained. I decided to add Redis caching to speed it up.

MY MISTAKE: I implemented aggressive caching without fully understanding 
the data freshness requirements. Patient records were cached for 1 hour. 
During that hour, if a doctor updated a prescription, other doctors seeing 
the patient would see stale data. Potentially dangerous.

We caught it during testing, but the incident taught me:
1) In healthcare, 'fast enough' with wrong data is worse than slow but correct
2) Every optimization decision has compliance/safety implications
3) I needed to understand domain requirements before architecture decisions
4) Humble yourself to domain experts (doctors in this case)

RESOLUTION: 
- Implemented cache-invalidation strategy coordinated with clinical workflows
- Set cache TTL to seconds instead of hours
- Added cache freshness logging for audit trails
- Involved clinical staff in testing

OUTCOME: System was faster (1s response) AND safer (always current data).

LEARNING: Healthcare isn't like consumer tech where 'move fast and break things' 
works. I learned to move fast AND be careful. This shaped how I approach 
regulated systems now."
```
